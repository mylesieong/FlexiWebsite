# Flexi Stretch — marketing site

A static marketing site for the Flexi Stretch app: a landing page, six SEO guide
pages, and the privacy policy. No framework, no runtime JavaScript — every file in
the repository root is either plain HTML/CSS or a generated artefact that can be
served as-is by any static host.

The site is mounted as a git submodule inside `mylesieong.github.io` at
`products/flexi/`, so it is served from `https://mylesieong.github.io/products/flexi/`
and never sits at the origin root. No link may start with `/`: templates write the
`{root}` placeholder, and `build.py` resolves it to the way back to the site root for
whatever depth the page lands at. The two hand-maintained pages, `index.html` and
`404.html`, are at the root and use plain relative links.

## Layout

```
index.html            Landing page (hand-maintained — bespoke layout)
404.html              Not-found page
privacy-policy.html   Generated (the URL in the store listings)
guides/               Generated SEO pages
css/style.css         Shared stylesheet
assets/img/           App icon and plan cover art, copied from the app
robots.txt            Generated once, checked in
sitemap.xml           Generated by build.py
build.py              Page generator
src/                  Page bodies + pages.json manifest + custom JSON-LD
_header.part          Shared header used by generated pages
_footer.part          Shared footer used by generated pages
_cta.part             Shared download call-to-action block
```

## Building

`index.html` and `404.html` are edited directly. Everything else is generated:

```
python3 build.py
```

That reads `src/pages.json`, wraps each body in `src/` with the shared `<head>`,
header and footer, injects the CTA block at each `<!--CTA-->` marker, emits the
JSON-LD, and rewrites `sitemap.xml`. Python 3 only — no dependencies.

Commit the generated HTML. The site is served from these files directly, so a host
never needs to run the build.

### Adding a guide

1. Write the `<article>` body as a new file in `src/`.
2. Add an entry to `src/pages.json` (path, body, title, description, headline,
   dates, and optional `faq` / `howto` blocks that become structured data).
3. Add the page to the `ItemList` in `src/guides-index.jsonld` and to the card grid
   in `src/guides-index.html`.
4. Run `python3 build.py`.

## Design

The palette in `css/style.css` is lifted verbatim from the app's `FlexiColors`
object in
`composeApp/src/commonMain/kotlin/com/municornio/flexistretch/ui/theme/Theme.kt`,
and the corner radii mirror `FlexiShapes`. If the app's theme changes, change the
`:root` custom properties to match — they are the only place colours are defined.

Plan artwork in `assets/img/` is copied from
`composeApp/src/commonMain/composeResources/drawable/`.

## SEO

Every page ships a canonical URL, a unique title and meta description, Open Graph
and Twitter card tags, and JSON-LD. The landing page declares
`MobileApplication` + `FAQPage`; guides declare `Article` + `BreadcrumbList`, plus
`HowTo` and `FAQPage` where the content supports them.

## Before going live

- [ ] **Set the real domain.** `SITE` in `build.py`, the absolute URLs in
      `index.html` and `src/*.jsonld`, and the `Sitemap:` line in `robots.txt` all
      currently point at `https://www.flexistretch.app`.
- [ ] **Set the real App Store ID.** The App Store buttons in `index.html` and
      `_cta.part` link to a placeholder `id0000000000`. The Play link is already
      correct (`com.municornio.flexistretch`).
- [ ] **Fill in the privacy placeholders.** `src/privacy.html` still carries the
      ⚠️ markers from `../PRIVACY_POLICY.md` (legal entity, contact email, postal
      address, Firebase retention period) and a visible draft banner. Fill them in,
      delete the banner, rebuild — then point `URL_PRIVACY_POLICY` in `Constants.kt`
      and the store listings' privacy fields at the live page.
- [ ] **Decide on terms of service.** There is no `terms.html` and the footer does
      not link to one, matching the app (iOS uses Apple's standard EULA, Android
      shows no terms row).
- [ ] **Add real screenshots.** The hero currently uses a CSS-drawn phone mock-up
      rather than a capture of the app.
- [ ] **Add an Open Graph image.** All pages currently share the 1024×1024 app icon;
      a 1200×630 image renders better in social previews.
